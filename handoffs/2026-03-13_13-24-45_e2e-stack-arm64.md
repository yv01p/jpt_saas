## 3. Mental Model (Most Critical Section)

**Why the current approach was chosen:**
The CI `docker-compose.ci.yml` was designed for GitHub Actions (AMD64 ubuntu-latest). This VPS is ARM64 (aarch64). The base `docker-compose.yml` pins postgres and redis to AMD64-specific SHA256 digests which fail with `exec format error` on ARM64 with no QEMU emulation available. The approach is to override those images in `docker-compose.ci.yml` with multi-arch tags (no SHA pin), and add `user:` overrides to bypass the gosu/su-exec user-switching that fails when `cap_drop: ALL` + `no-new-privileges: true` are in effect. All other services (minio, worker, api) are ARM64-compatible or architecture-agnostic.

**Codebase Gotchas Discovered This Session:**
- `api/src/main/java/org/jphototagger/api/security/JwtService.java:49` — rejects any JWT secret starting with `ci_test` unless Spring profile is `dev` or `test`. The `.env.ci` file uses `ci_test_jwt_secret_that_is_at_least_32_characters_long`. The fix: add `SPRING_PROFILES_ACTIVE: test` to the api service in `docker-compose.ci.yml`.
- `docker-compose.ci.yml` port override **does NOT remove** the base `["80:80", "443:443"]` ports — Docker Compose merges arrays. Port 80 was already taken by Caddy (`sudo systemctl stop caddy` was the fix).
- MinIO ARM64 image (`minio/minio:RELEASE.2025-09-07T16-13-09Z-cpuv1`) has no `curl` but has `mc`. The healthcheck was updated to use `mc alias set + mc admin info`.
- The MinIO init container (`minio/mc`) can't write `/root/.mc` due to `cap_drop: ALL` blocking `mkdir`. Fix: set `MC_CONFIG_DIR: /tmp/mc` env var.
- `security_opt: []` in a Compose override does NOT unset `no-new-privileges:true` from the base — arrays merge. To bypass gosu, set `user: redis` / `user: postgres` so the entrypoint skips user-switching entirely.

**Dead Ends — Do Not Repeat These:**

| Approach Tried | Why It Failed | Evidence |
|---------------|---------------|----------|
| Use AMD64 SHA-pinned redis/postgres images on ARM64 | `exec format error` — no QEMU emulation | `docker logs jpt_saas-redis-1: exec /usr/local/bin/docker-entrypoint.sh: exec format error` |
| `cap_drop: []` + `security_opt: []` in CI override | Docker Compose **merges** arrays, doesn't replace. `no-new-privileges` stays active. | redis still failed with `operation not permitted` |
| Override nginx `ports: ["8080:80"]` in CI | Compose merges port arrays, so 80:80 AND 8080:80 both bind — 80 still conflicts with Caddy | nginx startup conflict |
| `docker run --platform linux/amd64 busybox uname -m` | `exec format error` — QEMU not installed on this host | Verified no emulation available |

**Key Decisions Made:**

| Decision | Rationale | Alternative Rejected |
|----------|-----------|---------------------|
| Stop Caddy to free port 80 | Simplest fix; port arrays can't be removed via Compose override | Changing nginx to port 8080 requires changing Playwright baseURL and nginx.ci.conf |
| `user: redis` / `user: postgres` in CI override | Bypasses gosu/su-exec privilege-dropping without needing capabilities | Dropping `cap_drop`/`security_opt` via `[]` — Compose merges, doesn't replace |
| `MC_CONFIG_DIR: /tmp/mc` for minio-init | Gives mc a writable config location without changing security settings | Adding tmpfs mount for `/root` |

**Assumptions in Play:**
- Spring Boot recognizes `SPRING_PROFILES_ACTIVE=test` env var — standard Spring behavior, should work
- The `test` profile bypass in `JwtService.java:39` (`acceptsProfiles(Profiles.of("dev", "test"))`) will accept a profile named `test` — confirmed by reading the source
- After adding SPRING_PROFILES_ACTIVE, the API will start successfully — no other CI-secret guards exist in the codebase (spot-checked)
